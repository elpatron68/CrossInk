# Email Bridge — Account Lifecycle Cleanup & Signup Rate Limit

Date: 2026-10-05  
Status: approved  
Scope: `services/mail-bridge/` (store, auth, cleanup worker, pairing UI, config)

## Goal

Open one-click pairing makes accidental and abusive account creation cheap (browser
reload is enough). Add:

1. Staged deletion of unused / long-inactive accounts
2. Per-IP rate limiting on `POST /v1/accounts` only
3. Clear EN/DE UI copy so users know the retention rules

Device sync endpoints stay unlimited. Deployment expects nginx Proxy Manager in front.

## Decisions

| Topic | Choice |
| --- | --- |
| Approach | In-process activity tracking + in-memory signup rate limit (A) |
| Never-used retention | `ACCOUNT_UNUSED_DAYS=7` (no successful Bearer auth) |
| Inactive retention | `ACCOUNT_INACTIVE_DAYS=365` (after first auth) |
| Activity signals | `devices.last_seen_at`, plus any `items.received_at`, plus `users.created_at` |
| Rate limit target | Signup only (`POST /v1/accounts`) |
| Rate limit default | `SIGNUP_RATE_LIMIT_PER_HOUR=5` per client IP |
| Proxy | `TRUST_PROXY=true` — client IP from `X-Forwarded-For` / `X-Real-IP` |
| Rate limit storage | In-memory sliding window (resets on process restart) |
| UI | Pairing page warns about 7 / 365; show friendly 429 text |

## Activity model

### Schema

Add nullable column on `devices`:

| Column | Type | Notes |
| --- | --- | --- |
| `last_seen_at` | TEXT NULL | ISO-8601 UTC; set on successful Bearer auth |

Migration: `ALTER TABLE devices ADD COLUMN last_seen_at TEXT` when missing (same
startup pattern as existing schema init).

### Touch points

On every successful `require_device_token` resolution (pending / content / ack),
update `last_seen_at` for the matching device row (best-effort; log and continue
on failure so sync is not blocked).

### Per-user activity timestamp

```
activity_at = max(
  coalesce(max(devices.last_seen_at), ''),
  coalesce(max(items.received_at for user), ''),
  users.created_at
)
```

ISO-8601 UTC strings compare lexicographically when generated by the bridge.

Mail receipt counts as activity so a user who rarely opens the reader but still
receives books is not purged as inactive.

## Staged account cleanup

Extend the existing orphan cleanup loop (or a sibling worker on the same interval)
to also purge accounts.

| Stage | Condition | Env | Default |
| --- | --- | --- | --- |
| Unused | No device of the user has `last_seen_at` set, and `created_at` older than N days | `ACCOUNT_UNUSED_DAYS` | `7` |
| Inactive | At least one `last_seen_at` exists, and `activity_at` older than M days | `ACCOUNT_INACTIVE_DAYS` | `365` |
| Interval | Same worker tick as orphan cleanup | `ORPHAN_CLEANUP_SECONDS` | `3600` |

`0` disables that stage. No separate account-cleanup interval key.

### Delete cascade

For each matching `user_id`:

1. Delete files under `$DATA_DIR/items/{user_id}/` (best-effort)
2. Delete `items` rows for that user
3. Delete `devices` rows for that user
4. Delete `users` row

Log counts per run (`unused` / `inactive`). Do not touch other users’ queues.

Unknown-alias IMAP delete and pending-orphan purge remain separate concerns.

## Signup rate limiting

### Behaviour

- Only `POST /v1/accounts`
- Key: client IP string
- Window: rolling 1 hour
- Limit: `SIGNUP_RATE_LIMIT_PER_HOUR` (default `5`)
- Over limit → HTTP `429` with stable JSON detail (e.g. `"Rate limit exceeded"`)
- `SIGNUP_RATE_LIMIT_PER_HOUR=0` disables limiting

### Client IP behind nginx Proxy Manager

When `TRUST_PROXY=true` (default **true** for this deployment profile; document
clearly in `.env.example`):

1. Prefer left-most / first entry of `X-Forwarded-For` (nginx PM appends correctly
   when the proxy is the only trusted hop)
2. Else `X-Real-IP`
3. Else direct peer (`request.client.host`)

When `TRUST_PROXY=false`, always use the direct peer (safe for local/dev without
proxy). Operators running the bridge exposed without a scrubbing proxy must set
`TRUST_PROXY=false` so clients cannot spoof `X-Forwarded-For`.

### Storage

Process-local sliding window of timestamps per IP. Acceptable to reset on restart
and not to share across multiple bridge replicas (single-instance assumption for
Phase 2 / current ops).

## Pairing UI

Update `app/static/index.html` EN/DE strings:

- Always-visible or post-create hint: unused accounts (never synced) are removed
  after **7 days**; accounts with no sync and no mail for **365 days** are removed.
- On HTTP 429 from create: show a clear rate-limit message (EN/DE), not a generic
  failure.

No firmware changes.

## Configuration summary

```env
ACCOUNT_UNUSED_DAYS=7
ACCOUNT_INACTIVE_DAYS=365
# 0 disables the matching stage

SIGNUP_RATE_LIMIT_PER_HOUR=5
TRUST_PROXY=true
```

Account purge runs on the existing `ORPHAN_CLEANUP_SECONDS` tick.

## Out of scope

- Multi-replica shared rate-limit store (Redis)
- Captcha / proof-of-work
- True multi-device UI
- Rate limiting `/v1/pending`, content, or ack
- Firmware changes

## Verification

- Unit/API tests: unused purge (no `last_seen_at`, old `created_at`); inactive
  purge (old `last_seen_at` / mail); young or recently active users retained;
  mail-only activity prevents inactive purge; signup 6th request in window → 429;
  `TRUST_PROXY` IP extraction with `X-Forwarded-For`
- Manual: pairing page shows retention copy; nginx PM path still rate-limits per
  real client IP

## Non-goals / risks

- Spoofed `X-Forwarded-For` if `TRUST_PROXY=true` without a trusted reverse proxy
- In-memory limits do not protect across multiple bridge workers/hosts
- Clock skew is ignored (operator-controlled UTC timestamps)
